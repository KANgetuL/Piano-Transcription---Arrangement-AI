# PianoTrans AI 项目总规划

## 规划原则
- 以 P0 核心链路为先：上传 -> 模式选择 -> 扒谱 -> 预览 -> 导出。
- 优先保障 PC 端可用性，再扩展 Web 端能力。
- 工程约束按 architecture > coding_standards > naming_conventions 执行。

## 里程碑规划
### M1（第 1-4 周）需求与底座
- 产出: PRD 定稿、技术选型、PC 端基础 UI 框架、模型可调用 Demo。
- 验收: 可上传 MP3/WAV 并完成最小扒谱流程验证。

### M2（第 5-8 周）PC 核心能力闭环
- 产出: 模式选择、进度控制、乐谱预览、基础编辑、MIDI/MusicXML 导出。
- 验收: 端到端稳定执行，核心操作响应 <= 1s（非模型计算部分）。

### M3（第 9-12 周）PC 优化 + Web 起步
- 产出: 离线运行、设置中心、批量能力；Web 端上传/扒谱/预览基础能力。
- 验收: PC 连续运行稳定，Web 主流程可演示。

### M4（第 13-24 周）上线准备与扩展
- 产出: Web 导出与兼容性优化、测试闭环、上线文档。
- 验收: PC + Web 版本通过验收并可发布。

## 风险与缓解
- 风险: 模型推理耗时过高。
- 缓解: 引入快速/高精度双模式，异步任务与缓存策略。

- 风险: 跨端一致性不足。
- 缓解: 统一领域模型与导出协议，先做契约测试。

- 风险: 文档与实现偏离。
- 缓解: 每周文档同步检查，变更先更文档后改代码。
