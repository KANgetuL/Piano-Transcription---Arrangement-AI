# 系统架构（v0.1）

## 目标
- 支持音频到钢琴谱的端到端处理。
- 支持多风格改编与结果导出。
- 支持 PC 优先、Web 可扩展的架构路径。

## 分层设计
- Presentation 层: 桌面 UI / Web UI，负责交互与状态展示。
- Application 层: 用例编排（上传、扒谱、预览、导出）。
- Domain 层: 音符、小节、和弦、谱面等核心模型与规则。
- Infrastructure 层: 模型调用、文件系统、缓存、导出器、日志。

## 核心模块
- Ingestion: 音频上传、格式校验、元数据提取。
- Transcription: 分离、音高识别、节拍估计、和弦分析。
- Arrangement: 按模式生成普通/流行/电子/古典/黑乐谱。
- Editing: 音符与和弦编辑、节奏调整。
- Export: MIDI、MusicXML（后续 PDF/PNG）。

## 关键约束
- 模型核心逻辑不可改，仅做适配封装。
- 所有长任务必须异步可取消，并可反馈进度。
- 导出层与领域层解耦，避免格式耦合。

## 目录映射
- src/app: 入口与流程编排。
- src/services: 模型与外部服务适配。
- src/models: 领域模型。
- src/utils: 通用工具。
- src/config: 配置管理。

## 非功能设计
- 性能: 3 分钟音频在推荐配置下目标 <= 30s。
- 稳定性: 任务失败可重试，错误可追踪。
- 可扩展: 新模式与新导出格式应插件化接入。
