# 编码规范（v0.1）

## 通用原则
- 先可读后炫技，优先直观实现。
- 单一职责: 函数尽量只做一件事。
- 禁止静默吞错，异常必须记录并带上下文。

## Python 规范
- Python 版本: 3.10+。
- 风格: 遵循 PEP 8，行长建议 <= 100。
- 类型: 公共函数必须添加类型注解。
- 文档: 公共模块/函数需包含简短 docstring。

## 结构规范
- 业务逻辑不写在 UI 事件回调里。
- 模型调用通过 service 层统一封装。
- 配置项统一放在 config，并支持环境覆盖。

## 错误处理
- 使用明确异常类型，不使用裸 except。
- 错误消息格式: [模块] [动作] [原因]。
- 用户可见错误需提供可执行的下一步建议。

## 日志规范
- 日志级别: DEBUG/INFO/WARN/ERROR。
- 禁止输出敏感路径和隐私信息。
- 关键事件: 任务开始、取消、完成、失败必须落日志。

## 测试规范
- 单元测试覆盖核心领域逻辑。
- 集成测试覆盖上传到导出主链路。
- E2E 测试覆盖关键用户场景。
- 临时测试文件命名: test_<task>_<timestamp>.<ext>。

## 代码评审检查项
- 是否符合分层。
- 是否有必要测试。
- 是否存在重复逻辑。
- 是否破坏既有接口。
